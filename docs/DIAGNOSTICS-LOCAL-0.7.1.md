# 0.7.1 本地诊断候选：实际范围与同步状态

本次新诊断核心模块写入 GitHub 时被工具安全检查拦截；没有改用其他接口上传同一代码。此 PR 只有 README、说明与问题模板，运行代码仍为0.6.0。会话交付的0.7.1候选包含日志实际实现，不是GitHub产物。

## 日志怎样用

工作台侧栏/旧面板 → 诊断日志 → 开启30分钟记录 → 复现一次 → 停止 → 单次操作或异常筛选 → 预览/导出JSON。反馈时另写操作步骤、预期和实际表现、控件类型；不要附真实简历、Cookie、配对码、完整岗位链接或含个人信息截图。

记录开始/结束、扫描匹配后各字段状态、填写回读状态、控件类型、当前操作字段编号、数量、耗时、固定原因码与事件版本。工作台“诊断 #N”对应本次扫描顺序，筛选和翻页不改编号；重扫/映射后以新的编号为准。编号不等于稳定站点选择器。日志没有字段标签，仍可能需要虚构最小HTML复现来确定根因。

覆盖本地工作台和经后台执行的MCP抽屉；旧独立面板扫描/填写有受信消息跨度记录；早期UI脚本只收集未处理异常类别，不抓取console、网页全文或原始错误。导入被界面正常捕获的格式错误未必有细分类别，不宣称所有错误都能仅凭日志定位。

“ready/可填写”不是“verified/回读通过”；部分结果会标partial。只有开始可能意味着正在运行、已停止录制或后台中断，不能判定失败并盲目重试。

## 保存与隐私

默认关闭，单次30分钟；本机storage限制可信上下文，仅扩展诊断页可读/导出/清空。采用白名单重建事件，并在读出/导出时再次过滤。没有简历内容、字段标签、URL/域名、文件名、HTML、截图、Cookie、密码、配对码、文档ID或原始报错栈。导出省略绝对时间。

最多600条事件；每操作最多400条字段详情，优先保留异常并明确省略计数。读取/写入时清理24小时前记录，不活动时不保证立即物理擦除。清空同时停止，迟到结果不能补回旧记录；不触碰资料库数据。

事件按批异步写入，不逐字段调用storage，不等待日志磁盘操作才开始停止/填写。待写批次有上限，极端故障可能丢日志；诊断失败不改变调用者已成功的结果，也不触发重复填写。日志没有额外口令加密，事件序列和版本等仍是活动元数据，请先预览再分享。

## 没有扩大宣传的能力

日志不解决所有跨域iframe、级联、虚拟控件或附件回执。没有新整表耗时对照，不新增模型、云端日志或遥测；原500毫秒回读保留。本地DOCX导入/资料方案/复制延续0.7.0候选范围，仍不是任意格式自动解析或独立简历副本。桥接依旧不是TLS，静态加密不保护已被控制的操作系统/浏览器，也不能收回网站或模型已收到的内容。
