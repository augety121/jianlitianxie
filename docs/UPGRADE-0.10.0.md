# 0.10.0 经历补填与可定位日志

## 使用

1. 保留原扩展 ID 和本地资料。在原扩展目录更新程序，到 Edge 扩展管理页重新加载，不卸载、不清空存储。
2. 关闭旧插件管理页。在申请网页点击工具栏插件，重新打开管理页；先确认页底版本是 0.10.0。已有网页内容不要随意刷新。
3. 上传文字型 PDF / DOCX，逐项核对解析结果后保存。原先导入的 JSON 仍然可用，不必重复导入。
4. 在申请页点击“填写简历”。扫描自动对应已有经历，并按简历资料顺序对应空白经历卡片；管理页可以改选。歧义经历、敏感项、缺资料和未支持控件仍需人工核对。
5. 已有内容相同则保留；不同内容在管理页显示差异，确认后才修改。每次填写有旧值检查和回读，不自动提交。

## 本次重构

- 将经历解析抽成 record-resolver，接入默认本地扫描，不再依赖隐藏的“按顺序匹配”操作。
- 已填写学校、公司或项目名称的卡片先占用对应资料，空白卡片不会重复使用。两段经历同名且不能区分时停止猜测。
- 分离语义 section 与具体记录容器，识别 section 下的多张普通 div 卡片。
- 原生输入完成 focus → setter → InputEvent → change → blur → readback，聚焦后再次检查目标及旧值。
- 不能匹配时默认展开具体待处理项。

## 日志怎么定位

自动问题日志保留最近 24 小时、最多 80 次操作，每次最多 300 个字段；截断与记录失败会显示数量。导出前可以预览。

每项包含：当前扫描字段序号、固定规范字段名、分区、控件类型、是否标记必填、下拉选项数量、同字段资料数、同分区资料数、已确认资料数、最终候选数、经历对应方式、状态、原因码、失败阶段及下一步。

| 现象 | 定位依据 | 处理 |
| --- | --- | --- |
| 规范字段 unknown | 原始标签不在诊断白名单，可能尚未识别 | 对照管理页字段名；unknown 本身不等于填写失败 |
| 同字段 0 | 没有相同字段/别名资料 | 检查简历解析、补充字段或已确认资料 |
| 同字段有、同分区 0 | 资料分区或页面分区错误 | 核对 education/work/project 等分区 |
| 已确认有、record-unbound | 多段经历没有唯一对应 | 管理页选择具体经历 |
| option-unavailable | 控件当前选项无法精确匹配 | 完成上级选择、重扫或补充适配 |
| existing-unverified | 保留网页内容，无法判断对错 | 看 evidenceCode；不能称为核验通过 |
| invalid / needs-user | 格式校验或执行回读未通过 | 检查页面实际内容，避免重复写入 |
| verified | 本页回读一致 | 不表示网站已保存或已提交 |

日志不存原始标签、简历值、简历文件、证件、联系方式、网址、Cookie 或异常原文。字段名仅来自代码固定白名单。旧日志没有这些新证据，需要升级后重新扫描。

## 验证边界

本轮 Node/合成 DOM 验证覆盖多卡片分别补填、已有卡片占用资料、同名歧义、输入生命周期、差异修正和诊断脱敏。浏览器权限核验故障阻止了真实思谋页面及本地可视化读取；未把这些项目标为通过。未知网站控件仍需要真实复现和适配。
