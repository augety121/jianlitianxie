# 0.8.3：申请页直接填写与单项补填

## 对应的真实反馈

0.8.2页内面板只在扫描得到可填字段时才显示确认填写按钮。用户的实际截图为0可填、6未匹配、1人工、13保留，因此主按钮消失，流程又返回整页管理台；这不是用户不会操作，而是空结果路径设计错误。截图还显示“专业”“项目介绍”等未分区，但没有登录态网页DOM或原资料，不能仅靠截图宣称已查明所有缺项根因。

本次改为页面常驻“填写简历”。已核实资料后，一次真实点击授权一次新扫描及最多60个普通空白字段的填写。单独的“仅检查缺项”只扫描；收起后的同名按钮也直接填写。即便零匹配，主按钮仍保留，并在原页解释哪些项需要处理，不导航到管理页、不覆盖已有值来制造成功率。

## 小窗单项补填

待处理行提供“补填这项”，打开470×650的扩展自身窗口。候选与内容不放到招聘网页DOM；窗口持有随机短时票据，绑定申请页文档、标签页、原计划、资料修订号与新窗口身份。只允许该窗口读取候选和明确确认一个字段。新扫描、编辑资料、导航、停止或超时使旧票据失效。普通网页即使取得票据也不能读取候选；无密码/验证码/附件/声明等任意动作接口。

搜索只用字段与经历标签，不用隐藏的私人值；选择后显示预期内容，确认后只写这一项并回读。票据和候选不持久化；后台回收导致票据消失时重新打开，不偷偷恢复授权。关闭窗口不执行填写。小窗初始化只允许对尚在创建中的读取做有限重试，写入从不自动重试。

## 分区和经历识别

旧执行器依赖section、fieldset或已知record类名，普通div多列页面可能没有分区。本次增加限定的近邻分区标题回退：只采纳浅层、短文本、明确标题，排除导航、链接、按钮和多标题冲突；其容器同时纳入现有实时节点和结构校验。标题改变、区块移动后旧授权失效。

精确学校/企业/项目名称可用作已有经历的锚点：限定相同分区，匹配已核实事实，且只有一个一致的经历候选时才补全其它字段。同学校多个学位、矛盾锚点或分区未知不能据此猜测。显式整段绑定继续优先。新增企业名称/工作描述的明确同义词，不使用模型或全局模糊匹配。

## 验收层次

`tests/oneclick.test.mjs`：小窗权限、单字段确认、失效/取消/导航/改资料、固定缺项信息与锚点歧义。

`tests/oneclick-browser.py`：真实Chromium及生产engine/planner/page-assistant，用虚构div布局复现，Chrome消息接口为替身。`--layout-only`只做about:blank的6项布局/定位逻辑，明确不验证页内入口；正常模式12项包含真实鼠标一次点击、脚本点击拒绝、收起按钮、零匹配、只读检查和停止竞态。

`tests/page-entry-mv3.py`：实际安装，使用鼠标操作原页入口和真实扩展小窗，独立读取网页值，检查敏感/已有值不变、无自动提交和日志不含隐私。仅测试副本预授予虚构localhost来源及工具栏来源标记，CDP用于定位闭合Shadow DOM的测试按钮，不改变isTrusted、权限或CSP。

本机管理策略禁止导航到测试URL，完整页内浏览器层记录不可用；允许的about:blank布局与已有回归正常单独运行，不修改策略。完整测试由本提交CI执行后再报告结果。未验证Hotjob登录态官网，不把截图模拟当作官网兼容保证。

没有增加网络或权限，500毫秒延迟回读保留，不自动提交。本轮重点是完成实际操作路径与缺项恢复；未发布相对上一版的整表速度百分比。原自动性能回归保留。

机制依据：[Chrome内容脚本隔离](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)、[扩展窗口](https://developer.chrome.com/docs/extensions/reference/api/windows)。隔离不能抵御已攻陷浏览器；普通页内浮层不是可信的完整隐私边界。
