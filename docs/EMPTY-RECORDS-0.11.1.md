# 0.11.1：多行资料、零卡片新增与姓名识别

## 修复范围

此前现场日志只记录到少数普通字段写入，没有新增阶段。这不能证明新增曾执行；源码中的新增开关、输入资料完整性和零卡片结构必须分别核查。本版不把“没有尝试新增”说成“网页新增成功”。

MD 入口增加独立加粗字段名与下一段正文、内外冒号及混合行内字段边界。项目正文保留换行，正文内的“背景：”“方案：”不拆成新字段。原库保留，导入仍是本人核对后的显式合并；历史未保存的正文不能凭空恢复，应使用新入口重新读取原文件一次。

零记录区域不再依赖先存在 fieldset。支持纯 div 标题、直接标题文字、span 加号和相邻卡片区；分区边界、唯一新增按钮、逻辑身份控件计数、每次增长和旧内容都检查。已有卡片足够时不添加；结果不确定时不重试。一次任务可以执行多个上游校验的至多5条批次，总新增上限20。

只有存在已核实规范字段的教育、工作和项目记录计入目标。未知片段不会制造不可填的空卡片，缺少来源的家庭、健康、语言等级等不猜测。

姓名标签移除结构化校验提示和明确的必填错误尾句；提示消失不再使字段含义变化。已有内容、记录对应、视区命中与500毫秒最终回读仍保留。

## 原页操作与日志

点击“填写简历”先处理可确认内容。尚未允许新增时，原页显示“允许添加经历并继续填写”，明确列出各类缺少的记录数。单独点击后只保存当前网站的新增允许，不额外授予 Chrome 来源权限，不自动打开常驻；网站设置仍可关闭。

每次任务写入无值 add 诊断，区分未允许、没有来源、没找到区域、结构不明确、已经足够和实际新增。记录只含固定类型、数量和原因码，不含原始标题、网址或个人值。

## 分层验证

单元回归覆盖376条虚构字段保真、段落边界、来源过滤、隐私日志和授权设置。浏览器结构回归从零建立教育2、实习1、项目5，24个独立预期值校验；还覆盖平级分区、竞争按钮、校验提示及重复不新增。

`tests/empty-record-mv3.py` 安装实际扩展后，上传24条虚构MD、一次保存、原页点击先填写姓名/邮箱/简介3项，再由明确的新增允许动作创建8张卡片；一次反序经历选择后写入21个记录字段，独立核对全部24值。还检查脚本点击不能授权、重复不新增、未覆盖已有值、未提交、原库未被填写修改及日志不含私人值。

该新安装测试显式启用 Chromium 沙箱并检查启动参数，使用临时目录、由 Playwright 本地返回的保留 .invalid 地址，不启动 HTTP 服务或连接招聘网站；测试副本只预授予虚构来源，播种初始工具栏授权。它不是实际达梦账号、浏览器权限弹窗、所有控件或塔塔速度验收。

原本地、记录确认、恢复、页内与 MCP 安装回归继续在 CI 执行。运行结果必须以当前提交的日志/产物为准，不引用旧提交绿色状态。免口令资料仍是本地未加密保存；用户主动填写的内容会交给对应网站。

## CI 平台记录

新安装测试在 Windows 本机以 `chromium_sandbox=True` 跑通，并核对启动参数不包含禁用沙箱选项。Linux 托管运行器无法启动这个沙箱配置，失败记录保留；没有关闭沙箱或修改系统策略来规避。该新增测试独立放入每次 PR/Push 必跑的 Windows job，符合当前用户平台。原 Linux 控件、安装、MCP 和恢复回归仍保留，不降低断言，不设置 continue-on-error。
