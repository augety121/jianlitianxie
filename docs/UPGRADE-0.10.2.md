# 0.10.2：导出响应与部分项目补填

## 本轮修正

用户的 0.10.1 截图显示 102 个字段中 68 项未匹配，并出现数字字段名和导出弹窗卡顿。不能把旧版的合成测试通过当作真实页面已经修好。

- 导出原流程先刷新全部日志详情，再生成完整 JSON 预览，下载时再次序列化。现在列表每页 10 次操作，详情按需生成；导出直接读快照，不重绘列表。预览只有计数、原因汇总和最近操作前 3 项。
- 完整下载保留所有已采集的结构化字段，每次操作单独序列化并让出事件循环；进度显示在按钮上，关闭或离开页面可取消，重复点击不会启动多个导出。文件保留固定原因字典，去除重复的逐字段解释字符串。日志中原有 omitted/dropped 仍保留，不将采集上限说成完整页面覆盖。
- 修复“核对并保存网页内容”日志标题 undefined。
- 显式“起止时间”行支持开始年/月与结束年/月四个下拉框，以及带日的六个下拉框；“至今”复选框不参与日期拆分，也不会自动勾选。
- 数字 aria-label、placeholder 和邻接选中值不再抢占有效的结构标签。
- 名称为空但职责已填的项目卡片：只有不少于 30 个规范化字符的完整正文与一个已确认项目唯一精确匹配时，才绑定该项目。支持已保存长短版；共享正文、冲突的名称或不确定归属不推断。日志 binding=exact-content 表示此路径。

## 使用

1. 更新原来加载的 extension 目录，然后在 Edge 扩展管理页点“重新加载”。不要卸载原扩展，以免丢失本地资料。
2. 招聘页面有未保存内容时先保存草稿；从工具栏重新打开插件，确认浮窗和设置页版本是 0.10.2。页面引擎版本也会写入新日志。
3. 点击重新识别并补填；正确的已有内容保留，有差异在核对页确认后修正。
4. 问题日志点“预览并导出”，再点“确认导出 JSON”。弹窗摘要不是完整日志，下载文件才是完整已记录结构。不要重复导入同一份资料来解决字段识别错误。

## 参考源码

实际阅读用户提供的 resume-form-assistant-plugin-main.zip 中 content.js 的 scanFillableFields、getFieldLabel、findNearestGroupLabel，以及 form-agent.js 的重复经历分类。参考项目通过原生标签、容器与前序标签、placeholder、记录分组逐层定位。其扫描函数也没有提供可以直接保证思谋当前表单可用的专用适配器。

本轮针对当前插件独立实现范围日期、部分项目的证据匹配与导出分批处理，未复制其源码，也未接入其桌面程序或在线模型服务。参考入口：https://github.com/TshyGO/resume-form-assistant-plugin 。
