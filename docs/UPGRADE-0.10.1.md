# 0.10.1 下拉框已填值与整页保存

## 本次反馈与证据

用户提交的脱敏日志显示：扫描 102 个控件，90 个没有分区，34 条本地资料，候选检查次数为 0。截图中的已选年份和月份被作为待补字段标题。日志不足以证明资料本身错误，也不能确定网站使用的具体组件版本。

在合成表单中复现：下拉框用旁边的 span 显示已选值，内部搜索 input 为空。旧版会误读为空，或把选中值用作附近标签。现在支持旧版 Ant Select、React Select 以及具有明确 singleValue 标记的单输入分支，读取选中值并避开数值标签。明确的日期行按年/月/日拆分，并用所属记录的完整日期核验。平铺章节仅在标题有独立且不含输入框的容器时纳入识别；裸露的冲突标题保持待核。新增、隐藏或修改标题会使旧计划失效，深层标题同样校验。

## 更新与使用

1. 更新原扩展安装目录，去 Edge 扩展管理中重新加载，保留原扩展 ID 和资料，不卸载、不清空浏览器数据。后台和旧工作台都需更新，页脚应为 0.10.1。
2. 回申请页面，从浏览器工具栏重新点扩展。已填表不需要清空。点“仅检查缺项”：已读到的现有值保留；有资料且不同的值列入核对；缺项才补填。
3. 已填好的内容要复用时，点“读取本页已填内容，核对保存”。它重新读取当前页并打开核对窗口；选对经历和条目后保存。它不会替你提交，也不自动覆盖旧资料冲突。
4. “我补完了，记住内容”保留原来的增量行为，读取上次扫描后新增的内容。

## 新日志能判断什么

- 插件版本与引擎版本不同：可能还在用旧页面脚本；重新从工具栏打开。
- 资料清单只有 unknown：导入字段没有识别成规范名称，需要检查解析，而不是一直点填写。
- 字段是 unknown、数值未被读到或大部分分区为空：页面识别失败，不能直接断言是用户缺资料。
- 同字段资料有、同分区没有：分区不同；候选有但没有唯一经历：记录对应问题。
- 保留且已读到现有值：确实读取了内容，但只有 existing-consistent 才表示与资料核验一致。

日志只包含固定字段词表、数量、状态和版本；不导出原始字段标签、资料值、姓名、电话、网址或简历正文。旧日志不能追溯生成新增信息，需本轮重新扫描。
