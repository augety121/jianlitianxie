# 0.12.0：组件策略层重构与验证边界

## 从上传包得到的设计结论

五套参考插件均只做静态检查，版本和哈希见 UPLOADED-EXTENSIONS-AUDIT.md。可以借鉴的关键是按组件分开描述点击区域、搜索编辑器、提交后的显示节点、菜单及选项，而不是将所有下拉框当成一个普通input。产品脚本、品牌、账号和云端接口没有复制进项目。

## 实际拆分

- `src/autofill/engine-entry.js`：保留当前扫描、记录/页面身份、用户授权、已有值保护、500ms回读及任务生命周期。
- `src/autofill/component-catalog.mjs`：独立实现的组件接口目录，描述六类组件及新旧结构；只作用于原扫描已识别的字段，不扩大顶层扫描选择器。
- `src/autofill/select-driver.mjs`：由原选择流程抽离，通过已识别目标选择组件策略，保留原事件顺序、精确选项、等待及身份检查。
- `scripts/build-engine.mjs`：无第三方构建依赖的确定性打包，输出源文件摘要；发布检查比较源与产物，CI源码包包含src。
- `extension/core/execution-receipt.mjs`：仅固定阶段、是否开始输入和原因码能够通过工作线程进入日志，原始报错和私人值不导出。

## 已复现的缺陷

同一批独立合成组件测试中，0.11.1原引擎只通过3/9。Phoenix、Element、iView及ATSX的部分结构会超时；Phoenix和Element已有选中值也被读为空。原版失败结果被保留，不把失败样本移出分母。

新策略通过9/9：七种输入组件结构实际选择并读回，另两种已有值保持不动。包括Phoenix显示值、Ant现代/旧版、Element只读展示输入、iView、React Select及ATSX搜索。测试独立核对专业显示和邮箱值、选中次数，再次扫描均为保留。

迭代中还发现ATSX选择后替换占位内容、移除箭头会导致第二次扫描丢值。现在仅在原有单编辑器且标明选择器的候选范围内，用唯一提交显示节点识别它；原captureGuard、guardUnchanged、interactionGuard及记录字段边界没有删除或绕过。

## 日志

先前WorkspaceRun会把执行器回执降成单一status，页面打开失败、搜索失败和回读失败容易混成一个问题。本版在原范围/status验证之后，额外保留白名单阶段和attempted布尔值。未开始写入、已经开始搜索、完成回读能够区分，未知字符串被丢弃。

## 没有完成的范围

没有加入任意无input/ARIA语义div的全新发现逻辑，没有复制第三方MAIN世界桥接、读取React内部状态或绕过页面权限，没有新增跨域写入、自动提交或云端智能匹配。本轮不承诺所有站点或全部组件版本可用，不宣称达到塔塔速度。

新组件专用验证是实际浏览器DOM层，不是登录态ATS或五个产品本身的执行对照。独立的新组件安装测试未纳入本轮；原已安装扩展、本地资料、多经历、零卡片、恢复与MCP回归继续运行。结果只以当前提交的CI为准，不借用之前版本的绿色检查。

旧解析中没有保存的源资料不能凭模块更新凭空恢复。本版不删除、不自动重写用户资料，原多简历、导入和授权流程保持。原安装目录未被开发工作树覆盖。
