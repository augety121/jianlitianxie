# 0.8.2：申请页入口与零匹配反馈修复

本轮针对实际使用反馈：资料已经导入，用户仍停在重复导入页，不知道在哪里填写；申请网页没有本地填写按钮；扫描成功但没有可填写项。

## 依据与不能推断的部分

用户提供的0.8.1脱敏日志显示：成功导入34条，4次扫描均为20字段（13保留、6未匹配、1人工），没有fill阶段，匹配候选比较计数为0。日志没有字段标签、资料值或URL，因此不能确认具体哪一项被错误识别、哪个网址是目标，或原MD是否包含全部身份字段。原始用户日志、截图、文件名与个人资料均未提交本仓库。

采用等价的虚构20字段场景进行回归，而不是把用户资料写成测试样本。

## 新操作路径

已有本地资料时，从**真正的申请表页面**点击浏览器工具栏插件图标，会在该页右下角显示“本地简历速填”，不再强制跳转到管理页。

点击“扫描本页”，核对显示的普通空白字段清单，再点“确认填写上面N项”。普通字段每批最多60项，仅本次展示的条目会获准执行。敏感项、未匹配项、重复经历和更多字段仍到独立工作台核对，不靠模糊猜测直接写入。已有值不覆盖，不提交。

首次尚无资料时仍打开导入页。独立工作台顶部始终有“回到申请页 · 显示填写按钮”和“在工作台核对字段”。全部重复的导入预览显示“已保存，无需再次导入”和继续填写按钮，即使保存按钮被禁用也不会形成操作死路。标题显示目标申请页的网页标题和来源，避免把管理页当成申请页。每个目标页复用对应的管理标签页；同源导航在已有授权范围内恢复按钮。

这不等于安装后自动读取所有网站：未授权来源仍需本人点击工具栏。跨域框架、浏览器内部页面、已失去权限的页面仍有边界。

## 匹配与导入

支持MD“字段｜信息”“属性｜填写内容”等明确两列表头、中文/数字序号分区标题及个人信息标题。普通无标签段落仍留作未归类；不会自动补造信息。

预览显示姓名/手机/邮箱是否被识别，便于发现“看似导入成功但只读到了项目描述”。JSON仍推荐使用明确facts或JSON Resume。没有拿到原MD时不能保证这就是用户文件的全部原因。

零可填项直接说明有多少未匹配、人工、保留项；每行可定位真实网页或手动选资料。缺项增加固定原因码：no-label-match、record-unbound、ambiguous-source、date-precision。密码/声明等为restricted-control。只增加原因，不放宽匹配与现值保护。

## 安全与日志

页面内容脚本只得到页面已有标签、匿名字段ID与计数，不读取/返回完整主档、来源、未选值或日志。执行私有值仅在本人确认后发送给目标文档。消息校验扩展ID、顶层frame、活动文档ID、当前URL、已有来源授权、计划归属及资料修订号；页面不能借此停止其他工作台的任务。

网页DOM脚本触发的合成click不授权填写，真正输入还要经过现有控件遮挡/节点/字段语义与500ms回读。关闭Shadow DOM减少DOM干扰，但它不应被当作对恶意网页或受攻陷浏览器的完整安全边界。页面可能读取它最终收到的值，免口令本地资料仍未加密。

日志继续默认在本机保留，新增固定原因码经过存储/导出白名单过滤，不记录标签、简历值、URL、原始异常或截图。缺日志不意味着没有写入，不自动重试。

## 验证

`npm test` 增加页面能力边界、零匹配、一次性执行、敏感排除、文档变化、MD表头等回归。`npm run test:local` 增加全部重复后继续填写和20字段零匹配提示。

`npm run test:page-mv3` 用真实安装扩展验证MD导入、重复预览、返回申请页、鼠标扫描和确认、合成click被拒绝、独立DOM值读回、同源导航重挂按钮及脱敏日志。测试仅预授予虚构localhost来源并播种工具栏授权；保留正式CSP和关闭Shadow DOM，以测试端CDP定位按钮后发送鼠标输入，不修改扩展的isTrusted检查。它不是招聘官网、实际工具栏点击或权限弹窗验收。

本机没有成功取得安装后service worker，该层按不可用记录；远端是否通过以本次提交的CI报告为准，不沿用旧版绿色结果。
