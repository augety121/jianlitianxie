# 0.8.3：在申请网页直接填写

## 升级后从哪里点

先备份资料与原安装目录。把新版 extension 文件夹内容更新到原目录，在浏览器扩展管理页点击重新加载。不要卸载、清空扩展存储或删除已导入资料。关闭旧管理页，在真正的申请表标签页重新点击工具栏插件图标；旧页已经注入的脚本不会仅因替换文件就全部更新。

已有已核实资料时，右下角显示绿色的“填写简历”。点击一次，就为本页重新扫描并填写能够唯一匹配的普通空白项，每批最多60项。不需要先扫描，也不需要跳回资料管理页。填完后核对网页，保存和提交由本人完成。

“仅检查缺项”不会写内容；“我的资料”只用于资料维护。收起浮窗后的小按钮仍叫“填写简历”，也可以直接操作。尚未授权的网站需本人先点工具栏图标，不会安装后遍历所有打开网页。

## 匹配不到怎么办

零匹配时“填写简历”不会消失，旁边会展开待处理字段。点击该字段的“补填这项”，在扩展小窗里选择正确的资料，核对内容，然后点击“确认填入这一项”。只补所选字段，不需要跳到整页管理台。

小窗中的资料候选列表独立滚动；待填内容固定放在确认按钮上方。长内容可以单独滚动阅读，不会藏在底部按钮后。关闭小窗不填写。不要将错误经历的资料指定给当前字段；不知道的事实保持空白。

已有内容默认保留。附件、密码、验证码、声明和最终提交仍需本人处理，不因为没有自动匹配就强制填写。复杂控件或跨域框架可能不能自动填写；小窗也不能绕过浏览器权限或网站控件限制。

## 导入、日志与安全

保留MD/JSON/TXT导入、免口令本地存储、原加密库与可选MCP。免口令资料未加密，保存在本浏览器，不使用云端解析；主动填写进招聘网页的值可被该网站接收。

日志默认自动记操作阶段、耗时、数量和匿名字段状态，无个人值、字段标签、URL、密码或原始错误。出了问题，在“自动问题日志”预览后导出；不自动上传。不要把整份简历、账号、配对码或带登录态的网页地址放进公开Issue。

## 本轮实测边界

页内主按钮、零匹配时保留入口和单项小窗都有真实安装测试；测试使用虚构localhost页面和预授予的测试来源，不是用户Hotjob账号页面，也不验证所有招聘系统。

交付前发现小窗候选较多时，选中内容会落到确认按钮以下。tests/picker-layout.py以40个候选复现原布局失败，检查470×650和390×580小窗下的预览/确认几何位置、长内容滚动与一次写入。修复采用独立滚动区和非遮挡底栏，没有新增权限或放宽CSP。

npm run test:oneclick同时运行原17项页内/布局场景和4项新小窗回归；npm run test:page-mv3验证实际安装的原页操作和补填。完整源码可运行npm test与npm run check。各层是否通过以对应提交的CI与报告为准，不能用旧提交结果替代。
