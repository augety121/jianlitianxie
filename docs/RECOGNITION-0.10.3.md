# 0.10.3：修复“扫描成功但始终没有可填项”

基于已合并的0.10.2主分支 `7fc58c45`，不回退之前的PDF/DOCX、本地存储、MCP和核对修正功能。

## 本轮实际问题与证据边界

用户最新脱敏日志的末次扫描有102项：65未匹配（其中64条诊断为字段未识别）、34保留、3人工；没有执行回读。当前39条资料的诊断词表中35条为unknown。这并不证明35条都是错误信息：unknown也可能是词表外的项目细节。上传的ZIP实际是另一个开源参考项目，不是当前运行版本；工作基线因此取自本仓库0.10.2源码产物。Codex本地线程链接未被读取。

截图中出现“学校/专业显示选中值，但内部搜索框为空”和“就读时间由四个年月控件组成”的结构。没有登录态DOM，不能声称已在用户SmartMore账号实测。先用本仓库生产引擎构造同类结构，旧0.10.2在7个初始回归中6项失败：把选中值或下拉箭头当标签、丢失选中值和学校锚点、不识别就读时间、扫描菜单搜索框、把临时搜索当长期值、漏读多列表格。普通输入对照通过。

## 代码修复

自定义下拉按单个编辑器、组件标记、值/占位节点及指示器界定逻辑控件。不把整个表单、邻居字段或选项面板当成组件；识别出的显示值与搜索文字分开处理。选中学校成为整段教育经历匹配的证据；显示值不再作为字段名。多显示值保留，不当成空白覆盖或转成单个事实。

新增就读时间/在校时间等明确范围的四/六分量识别；年、月、日与开始/结束分别关联。仅转换已有日期，不推测缺失日期。选项的09月和资料中的9可按同一明确月份选择并回读。点击实际逻辑控件，不瞄准1像素搜索框；遮挡、禁用、文档、资料修订、现值、取消与500ms回读检查保持。

不再把下拉菜单里的搜索输入和导航搜索计作简历字段。扫描等待完成后开启新的同步元数据缓存，避免重复计算相同标签/日期结构；不把缓存跨异步等待或写入复用。

MD支持带备注等附加列的“字段/内容”表、明确分区/经历列，以及带身份列的横向教育/工作/项目表。只按明确表头解析，未知行仍显示在未归类区域；不猜测自由段落。新顶层标题不继承上一段项目的经历标识。已保存的原始事实不删除、不自动改写；之前未保存的原文无法从计数日志恢复。重新读取原文件会去重；已有网页内容可用原来的“读取本页已填内容，核对保存”明确导入。

诊断新增允许枚举的标签来源，区分词表外但有明确标签与真正没有标签；版本读取实际扩展清单，不再硬编码0.10.1。日志仍不保存原标签、个人值、网址或原始异常。
