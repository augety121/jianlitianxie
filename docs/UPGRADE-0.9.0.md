# 0.9.0 上传简历、补填与纠错

## 使用顺序

1. **先更新原插件**：如果原插件加载的是本仓库 `extension`，在 Edge 扩展管理页找到它，点击“重新加载”。关闭旧的资料管理页，再到原申请页点击工具栏插件。不要卸载或清空插件数据。其他目录安装的版本，可将本次包的 `extension` 内容更新到原扩展目录后重新加载。无需刷新有未保存内容的申请表。
2. **上传简历**：点击“导入 / 核对修正”→“导入与管理资料”，选择 PDF 或 DOCX。PDF 须有可复制的文字层，最多12MB/30页；DOCX最多8MB。仍支持 JSON/MD/TXT。
3. **核对解析**：字段名称、分区、所属经历和正文都可直接修改；漏识别的信息点“补充漏识别字段”。“对照简历原文”和“未归类内容”可查看未自动拆分的文字。只勾选真实、准确的条目，再保存。与已保存资料不同的更新默认不选，需要本人决定是否采用。
4. **对应多段经历**：进入“扫描与填写”，可点“按简历顺序匹配空白经历（先预览）”；核对每段学校/项目是否对应正确，必要时在每段下拉框改选。已填写的经历不按顺序重排。同一个学校对应多个学位等情况要单独选择。
5. **补填与纠错**：普通空白项可补填；一致的已有内容跳过；不一致的已有内容列出网页值和资料值，点“确认使用简历值”，再点底部“填写所选项”。原页浮窗不会批量覆盖已有内容。
6. **核对网页结果**：填写后回读并显示结果。网页新增一段、展开区域或切换下一步后重新扫描。附件、声明和最终提交仍由本人在网页处理。

## 本次针对的问题

用户提供的匿名日志有19次扫描、没有填写记录；每次48个字段、34条资料、0次候选匹配。日志不含字段名称，不能凭此断言是哪43项出错。截图显示多个普通 div 布局字段没有被识别。

- 接入 PDF.js 本地文字提取及已有 DOCX 安全读取器；无需模型API、桌面解析服务或云端上传。
- 增加中文简历分区、教育日期、两行项目标题、项目原文与职责段落、实习提取；保留来源及未归类文字。自动提取的全部是待核对草稿。
- 修复普通 div 标签的识别与多段项目卡片的所属区块；避免名称/角色与正文被拆成不同经历。
- 表单同时存在短输入“职责”和长输入“项目中职责”时，在明确项目分区下把前者作为角色，后者作为职责正文。
- 支持具有明确“入学/毕业/开始/结束”等标题的独立年、月、日字段。资料只有月份时不会自动补造日期。
- 增加逐项差异修正，保留写入前旧值检查、节点与经历检查、写入后回读及结果不确定时停止。
- 日志新增未识别字段名和未识别分区的计数，继续不记录简历值、字段名或URL。

## 验证范围

运行了 Node 自动测试、真实引擎在 jsdom 合成表单中的扫描/计划/写入/回读测试、管理页逻辑的 Word 上传→编辑→保存→计划测试，以及本地现有两页PDF文字提取检查。Node测试不代替浏览器布局、真实点击、React状态或已安装MV3验收。

**思谋网站尚未验收通过**：可以列出 Edge 中已登录的申请标签页，但认领页面被浏览器工具拒绝，原因为无法核验保存的浏览器权限。没有读取到该页实际DOM，没有向该申请表写入，也未提交。没有绕过此拦截使用其他浏览器/接口访问同一目标。

文字型常规单栏简历解析已覆盖；图片扫描件、复杂多栏、Word文本框、任意标题格式、封闭Shadow DOM、跨域iframe、虚拟列表及复杂联动不保证自动处理。未归类文字保留供核对。普通网页的“添加经历”还需本人点击再重扫，不能称为所有字段、所有站点已支持。
