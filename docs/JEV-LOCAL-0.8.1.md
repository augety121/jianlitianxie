# 0.8.1：Jev 思路的本地执行优化与准确性回归

## 不是接入云端 Jev

对照用户指定的 [jev-ultrafast 性能报告](https://github.com/browser-use/jev-ultrafast/blob/1231850a0bf1a0c0341fe408ef1668dbbfdfac46/docs/performance.md)与[实际 DOM 快照实现](https://github.com/browser-use/jev-ultrafast/blob/1231850a0bf1a0c0341fe408ef1668dbbfdfac46/jev_ultrafast/snapshot.js)，独立适配“批量观察、真实节点、局部语义守卫、事件等待、独立验收”的工程方法。本扩展没有调用 Jev / TypeSafe / Mercury / OpenRouter，不新增模型服务、调试端口或权限。Jev 的在线航班用时不作为本项目简历用时。

0.8.0 已有一次注入扫描、事件通知和控件等待，不重复把旧能力写成本轮新功能。本轮保留本地免口令、MD/JSON/TXT、自动日志与高级 MCP，聚焦填写执行期间的重复工作和错误成功判定。

## 实际代码变动

1. 同一段经历内的控件节点列表在一次填写任务中缓存。每次使用前先排空同步 DOM 变更记录；新增、删除、重排、role/contenteditable/class 变更使对应缓存失效。节点身份、父节点和区块顺序始终实时检查。标签、值、权限、几何位置与遮挡不缓存。
2. 字段名称按原有优先级找到第一个可用来源后立即返回，不再明明已有原生 label 却仍查询包装层和表格。配对测试比较两侧快照字段合同，避免优化改变扫描含义。
3. 保留每8次写入或8毫秒让出执行权的限制；支持时用 scheduler.yield，不支持时使用原 setTimeout 回退。没有并行填写、后台节流绕过或关闭安全检查。机制参考 [Chrome 官方说明](https://developer.chrome.com/blog/use-scheduler-yield)。
4. 普通原生输入同步拒绝值或报告无效时，停止后续字段；不等待整张表结束才发现第一项已被网站撤销。复杂控件继续按已有异步规则串行处理。
5. 最终仍等待500毫秒，但回读除了值还重新验证字段标签、经历位置、表单与控件语义。重复字段ID计划在写入前拒绝。已写后目标改变记为需要核对，不自动重试。
6. 扫描、匹配、执行、回读等数值耗时显示在本地流程与自动日志中。日志存储与导出都经固定数值白名单，不能借性能数据带入URL、标签、值或异常文本。高级MCP复用执行器，不被强制用于本地填表。

## 冻结基线与本机最终对照

基线提交 `8cdb273fc725ec6f771727456dfda02da5b05e58`（0.8.0）。四种虚构表单，每种6对、交替运行，全部48次尝试保留。每次独立检查实际DOM值、既有密码/声明未变以及未提交；两侧扫描合同一致。

计时为同一次浏览器调用中的“扫描 + 本地匹配 + 执行”，包含两侧相同的500毫秒延迟回读；不包含浏览器启动、页面准备、人工核对、云端模型、招聘网站网络或服务器保存。独立核对在计时结束后100毫秒进行。

## 准确性先失败再修复

同一套“延迟改字段名”和“延迟重排经历”的虚构页面，在冻结0.8.0上分别复现了错误的 verified；0.8.1两项均判为需核对。新增16项真实DOM测试覆盖记录缓存、同步节点插入、角色/编辑属性/类名改变、属性值改变、同步拒绝、取消、重复计划、回退调度、Shadow DOM与无关时钟更新，并核对观察器释放。

本机最终检查：Node118/118，原控件25/25，目标守卫16/16，兼容15/15，经历4/4，旧面板10/10，高级工作台14/14，本地工作台11/11，新增执行守卫16/16。UI层部分Chrome依赖为替身，控件层为真实DOM。

本机安装MV3未获得service worker，记录为不可用，不记通过。新增安装测试包含本地日志实际分阶段数据及迟到改名场景，交由CI中的完整Chromium验证；本文件写入时该提交CI尚待执行，最终结果以对应PR检查与产物为准。

新自动CI任务 jev-local-matched 对同一固定基线运行每种3对、共24次独立核对。原手动历史 matched-performance 仍保持原规则；跳过不算通过。不会为了绿色状态删除断言、放宽CSP或把验证失败当作纯速度数据丢弃。

README、package、manifest及默认本地页版本为0.8.1；高级加密页沿用原HTML，静态角标仍为0.8.0，实际运行版本请以扩展详情为准。该HTML的版本文字更新未获工具允许，未重传；不影响已更新的共享执行器。桥接兼容协议仍0.4.3/transport2。保持原安装路径、先备份，不卸载或清空浏览器存储。本地用户更新扩展即可，MCP用户更新完整源码并只重启对应桥接。原有未加密本地资料与加密库选择不变；自动日志仍不上传。

本轮没有新增跨域、闭合Shadow DOM、复杂级联、虚拟列表和附件服务器回执适配，也没有招聘官网成功率统计。填写到网页的值会交给该网站；最终500毫秒回读不是服务器保存/提交的证明。
