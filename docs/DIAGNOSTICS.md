# 诊断日志：复现一次，再定位问题

## 用户操作

在工作台侧栏或旧面板打开“诊断日志”，点击“开启30分钟记录”。保持原申请页，回工作台复现一次扫描、匹配或填写问题。回诊断页点击“停止记录”，可按单次操作或异常筛选，再预览和导出JSON。没有自动上传，也不用提供整份简历。

分享日志时另写：具体操作步骤、预期、实际表现、控件类型。工作台“诊断 #N”与本次扫描顺序对应；翻页和过滤不改变这个编号，重新扫描或映射后需以新编号为准。编号不是稳定网站选择器。日志本身没有字段标签，因此未知组件仍可能需要虚构的最小HTML页面才能定位根因。

## 实际记录的内容

开始/结束、扫描匹配后的各字段状态、填写回读状态、已核实资料数量（无内容）、控件类型、必填标识、当前操作内字段编号、被排除和截断计数、毫秒耗时、固定原因码、随机操作关联号以及事件记录时的插件版本。相同版本内，后台重建后仍可读取已经写入的日志。

覆盖新工作台的扫描、映射/经历绑定、定位、填写、取消、锁定、资料操作、MCP分享与撤销，以及经后台处理的旧MCP抽屉操作。旧独立面板的扫描/填写有单独的受信消息跟踪；提前加载的小脚本只记录界面未处理异常的类别，不拦截或上传console内容。浏览器安装失败、脚本在诊断模块加载前失败、后台被系统杀死时，最后事件可能缺失。

“可填写”不是“回读通过”；有未处理项会标partial。“开始但无结束”不强行判失败：可能仍在运行、已停止录制或后台中断，不能据此自动重试。现有值保留、人工控件、校验失败、页面变化、过期、配对失败等使用不同的固定原因码和处理提示。未经分类的异常只写INTERNAL，不写错误原文。

## 隐私与保存规则

默认关闭，单次开启30分钟。只写本机chrome.storage.local，限制TRUSTED_CONTEXTS；仅扩展诊断页可读取/导出/清空，网页不能通过猜消息名访问。日志未做额外密码加密，因此不保存简历值、资料标题、字段标签、URL/域名、文件路径、HTML、截图、Cookie、密码、token、文档ID、原始错误或调用栈。不复制任何真实浏览器数据到仓库。

字段采用白名单重建，不依赖“先全量记录再正则打码”。存储读取和导出再做一次白名单过滤；导出省略绝对时间，仅保留相对时间。版本、顺序、计数和行为仍反映活动元数据，分享前必须预览，不能承诺匿名化不可识别。

容量上限600条事件。每操作最多记录400条字段详情，优先保留异常，记录被省略数量；超限的旧事件滚动淘汰。读取或写入时清理24小时以前的日志，插件不活动时不保证立即物理擦除；“清空并停止”会清理当前数据并阻止旧操作的迟到结果补写。清空不会删除简历库。日志导出没有自动上传，备份口令/配对码不要放在Issue描述中。

一次操作按批写日志，不逐字段调用storage；日志写入队列不阻塞填写或停止操作，队列未完成时最多保留32个待写批次，极端故障可能丢失日志；日志存储错误不会变成再次填写的理由。保持500ms原有回读，未降低安全校验。日志只证明程序观察到什么，不能证明招聘网站已保存或申请已提交。

## 开发复现

`npm test`包含白名单、容量/期限、并发、后台重建、清空竞态、跨页身份、存储失败、生产调用路径和单次旧面板收据测试。`npm run test:diagnostics`使用真实浏览器界面和实际Node日志模块，Chrome消息为模拟。`npm run test:mv3`另检查安装后真实消息、存储隔离、本地与MCP填写日志及下载；该层用虚构localhost与预授予测试权限，不等于真实招聘官网或用户权限弹窗。

版本一致性检查会比较README的app-version标记、package.json、manifest.json以及工作台版本标识。桥接兼容版本0.4.3是协议标识，不等于产品版本。历史测试报告描述其对应提交，不得挪用为新版已通过。

旧独立MCP面板的可选诊断消息有250毫秒等待上限；消息丢失可能漏记，但不会因此无限等待。后台工作台/抽屉操作不等待日志存储完成。
