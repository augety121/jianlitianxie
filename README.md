## 为什么 README 之前不是 0.7？

0.7.0 上次只交付了本地候选包，GitHub 当时实际运行代码仍是 0.6.0。本轮在本地候选上继续加入诊断日志，形成 0.7.1；但新日志模块的 GitHub 写入被工具安全检查拦截，没有通过其他接口重传。因此不能只把标题和 manifest 改成 0.7，造成用户下载到不同能力的程序。

| GitHub main / 本 PR 运行代码 | 0.6.0 | 本地加密库、长表单审阅、JSON Resume、经历绑定、临时 MCP、控件校验 |
| 上次会话候选包 | 0.7.0 | 另加本地 DOCX 文字提取、命名资料方案、逐条复制 |

本地候选包不是 GitHub Actions 产物。GitHub 页面上的“Download ZIP”仍下载该分支实际代码，不能用它替代会话中的 0.7.1 包。候选源码的 README、package.json、manifest.json 和工作台标识已统一到 0.7.1，并增加本地发布一致性检查。协议兼容版本 0.4.3 / transport 2 与产品版本不是一回事。

## 0.7.1 本地候选：遇到填写问题如何留下日志

在工作台侧栏或旧面板打开“诊断日志”：**开启30分钟记录 → 回申请页复现一次 → 停止记录 → 按单次操作或异常筛选 → 预览并导出 JSON**。再补充操作步骤、预期结果、实际表现和控件类型。

记录扫描/匹配与填写/回读的状态、当前操作的字段编号、类型、数量、毫秒耗时、固定原因码、随机关联号，以及记录时的插件版本。日志默认关闭；没有自动上传。只出现“开始”不证明失败，不会自动重新填写。

日志不记录简历值、字段标签、URL、HTML、截图、Cookie、文件路径、密码、配对码、原始错误或调用栈。存储和导出均使用白名单过滤；导出只保留相对时间。事件序列、版本与计数仍是活动元数据，分享前请预览。

最多保留600条事件；每次操作最多400条字段详情，优先保留异常并标注省略数量。读取/写入时清理24小时前记录；不活动时不承诺即时物理擦除。清空同时停止记录并阻止迟到补写。日志异步按批写入，不逐字段写磁盘，不为了日志失败重试填写。

**以上日志目前只在本地0.7.1候选包。** [详细范围和同步状态](docs/DIAGNOSTICS-LOCAL-0.7.1.md)。

## GitHub 0.6.0 已有功能

工具栏打开独立工作台。本地模式不依赖 Node 或模型；支持手动编辑、TXT、facts JSON 和 JSON Resume 导入，导入先预览重复、变化和冲突，新增或更新内容仍须核实。资料加密保存，支持密文备份、恢复、锁定和换口令。

空白教育、工作和项目记录可以整段绑定对应经历，之后按字段语义匹配。同学校不同学位、同公司不同任职时间分别保留；记录重排、替换或增删字段后旧计划失效。网页定位只高亮实际节点，不点击或填写。

长表单支持分区、字段搜索、本次已选和必填待处理筛选。字段每页30项、资料每页60项、映射候选按需打开每页40项，翻页不丢选择。分页是展示限制，不等于只扫描当前30项。

原生输入写前检查格式、范围、步长和长度；密码/验证码及隐藏、禁用、只读字段不会直接进入填写。保留500毫秒延迟回读，未知事实不猜测、已有值不覆盖，不自动保存或提交。

同源 iframe 可在单独授权后枚举和扫描，但仍为只读；跨域、闭合 Shadow DOM、复杂级联、虚拟控件和附件服务器回执未全部支持。当前可观察字段数不是整站覆盖率。没有所有招聘网站零误填承诺。

## 三种数据路径

| 路径 | 来源 | 边界 |
| --- | --- | --- |
| 本地填写（默认） | 加密库中本次选择的事实 | 不调用桥接或模型；填写时只把选中值交给招聘网页 |
| 临时 MCP 协作 | 本人明确授权的事实和主页面结构 | 桥接内存最多5分钟；不写旧主档，所选内容会进入 Codex 上下文 |
| 原 MCP 主档 | 用户主动切换后的本机 profile.json / evidence.json | 历史文件仍为明文；不是新库的隐式镜像 |

临时授权撤销/到期后拒绝后续读取。已进入网页或模型上下文的内容不能靠撤销收回；浏览器崩溃或挂起不保证即时停止。loopback HTTP 加配对码不是 TLS，也不能防止已经控制系统或浏览器的恶意程序。旧文件不会自动加密或删除。

## 安装与升级

GitHub 0.6.0：加载 `extension` 文件夹，在具体申请页点击工具栏图标，核实资料、选择经历、扫描、审阅和填写。参考 [0.6.0安装](docs/INSTALL-0.6.0.md)。本地0.7.1候选请使用会话交付包及其安装说明，不混用版本。

升级先备份，在原目录替换公开代码并重新加载，不要先卸载或清空存储。MCP 用户同时更新 bridge 与 extension，只重启对应 resume_fill；不要结束无关 Node 程序。入口仍为 Node.js 22+ 运行 `bridge/server.mjs`，私有资料目录留在源码之外。
