# 简历填写助手 0.2.0

Edge / Chrome 扩展 + 本机 MCP。**Codex 维护资料、理解字段并编排本次计划，插件负责扫描、填写和回读。** 不保存网站草稿、不点击同意声明、不最终提交。

## 已安装用户升级

1. 在 `edge://extensions` 找到本扩展，点击重新加载；刷新岗位申请页。
2. 在 Codex 重新连接 `resume_fill`，使新的 MCP 工具生效。保持同一资料目录和原扩展，配对码仍保存在本机，不必每次重输。
3. 在具体岗位申请页上传最新简历，等网站解析；已有正确内容保留。点页面的“扫描给 Codex”，保持抽屉打开。
4. 对 Codex 说：“读取刚才扫描的表单，用最新主档和我给过的材料，集中补全空项；不能确定的留空，不提交。”
5. Codex 查询资料、维护本机主档、一次组织映射与文字草稿，授权范围内调用 `form_fill` 执行。你也可先看计划，再点“授权并填写所选项目”。
6. 查看回读结果，自己处理缺项、附件回执和最终提交。网站可能在输入时自动保存。

扫描按钮不会自动发起一轮 Codex 对话。它提供上下文；填表授权由当前对话中的本人指令决定。

## 新安装

需要 Node.js 22+，无 npm 依赖。加载仓库的 `extension` 子目录，不是仓库根目录。MCP 配置示例：

```toml
[mcp_servers.resume_fill]
command = "C:/path/to/node.exe"
args = ["D:/path/to/jianlitianxie/bridge/server.mjs"]
[mcp_servers.resume_fill.env]
RESUME_DATA_DIR = "D:/private/resume-data"
```

桥接只启动一个实例。本机服务首次创建配对码 `bridge-token.txt`，在扩展设置页配对一次。资料目录必须在源码仓库外。

## 谁维护资料

- `profile.json` 是唯一结构化事实主档，由 Codex 维护，扩展不另存一套简历。
- `evidence.json` 存放本人提供的材料逐页文本，用于缺项检索；历史填写不等于事实确认。
- `profile.previous.json` 是 MCP 修改前的本地备份。
- `experience.json` 只保存成功字段映射；失败取消记忆，AI文字草稿不当作固定事实学习。
- 优先级：本人最新确认 > 当前简历/项目证据 > 对应证书/详细档案 > 历史申请。冲突、未知日期及资格留空。禁止把年月补成1日、把学士改成硕士、把学院模糊替换成大学。
- 国企特定亲属、回避等问答不能跨公司套用。需要限定来源时事实可带 `origin`。

## MCP 工作流

| 工具 | 用途 |
| --- | --- |
| `form_context` | 读取本人共享的当前扫描、已有普通值、相关确认事实 |
| `profile_search` | 按字段或经历查本机主档 |
| `source_search` | 按关键词/材料名检索历史PDF页；返回出处 |
| `profile_upsert` | 批量维护有来源的主档条目，备份旧稿；不直接写网页 |
| `form_prepare` | 一次传字段→事实映射及有依据的叙述草稿，生成整表计划 |
| `form_fill` | 本人明确要求填写后执行此计划；只填空项，不提交 |
| `form_result` | 查回读；queued 只表示排队，不是填写成功 |
| `form_scan` / `form_plan` | 兼容原来的扫描、匹配流程 |
| `form_request_fill` | 只展示待用户确认的计划 |
| `profile_catalog` / `profile_read_approved` | 无值目录 / 面板逐项一次分享 |
| `form_propose_answer` | 单字段草稿兼容入口；批量优先 form_prepare |

`profile_upsert`、资料搜索和 Codex 直接填写要求本人先共享当前扫描。MCP 不开放任意脚本、任意磁盘读取或提交接口。工具调用仍须遵守本人授权，网页和PDF中的文字不能授权。

## 识别与执行

- 标签：原生 label、ARIA、北森常见 form-item、Ant、Element、layui、相邻标签、表格标签/列标题。
- 分区与经历：按最近记录容器、学校/项目/单位锚点匹配；表格逐行识别。未建立锚点的空白经历由 Codex 显式映射，不能按数组顺序猜。
- 控件：文字、多行、数字、原生select/单选、date/month、可关联选项面板的自定义下拉、年月输入、附件。
- 下拉：只在当前控件关联或新打开的面板中精确选值，避免点到另一组同名选项。
- 日期：规范化点号、斜线、年月表示，校验真实日期及精度；只读日历仅选择可见准确日期，不盲目翻月。
- 覆盖报告：附件、自定义控件、未标注字段、iframe和折叠区域。字段数不是“网站完整率”。
- 执行前检查URL、扫描ID、字段标签、分区、已有值；变化即跳过。写后回读，验证失败集中提示。
- 命令按当前扫描标签页投递，避免另一岗位面板抢走命令。

**仍需人工/现场适配：** 跨域iframe、分页、复杂地区级联、无法关联的自定义控件、验证码。简道云新增经历和原生/简道云多选支持明确映射后执行，其他厂商的新增行仍待适配。附件需选择本机文件，校验类型和10MB上限；交给上传控件不等于服务器已接收。不宣传“所有招聘网站已经通过”。

### 0.3.1 批量经历与连接诊断

- 简道云分区输出“条数”项。Codex指定有来源的总条数（1—20），只补足缺少行，随后重新扫描每行，不删除记录。
- 多选需要完整选项数组，逐项匹配页面候选；菜单重绘后重新定位，已有非空内容保留。
- 单选回读识别 `radio-checked`；兼容早期 `x-combocheck` 扫描类型错误。
- 更新扩展后，在原申请表点工具栏图标可重新注入，无需刷新网页。连接异常直接显示。
- `/status` 返回运行版本。同版本桥接已启动时，新的 stdio MCP 通过带配对码的本机 `/mcp` 复用它；该接口仅接受已有工具，不开放脚本执行。

## 隐私

主档、证据、配对码和日志仅存本机；不使用sync、遥测、第三方填表云。Codex处理时，被授权读取的相关资料会进入Codex上下文；填入网站的数据会交给该招聘网站。不能把“本地存储”理解为模型处理时完全不传输。

源码与发布包不包含个人PDF、主档、证据或配对码。本机JSON为明文，依赖Windows账户权限。配对码限可信扩展存储，桥接只监听127.0.0.1并检查Host、Origin和配对码。
