# 简历填写助手 0.8.1

**本地优先：导入一次 → 点击插件扫描 → 核对后填写。** 默认入口不依赖 MCP / Codex，不要求创建口令。资料不主动上传；输入招聘网页后，该网站可以读取并可能自动保存你填写的值。

## 0.8.1：更少重复遍历，更严格的回读

参考 Jev 的批量观察与局部目标守卫思路，独立优化本地执行器，不接入 Jev 云端模型。经历控件结构缓存随相关DOM变更失效；字段标签按优先级短路读取；支持时使用协作式调度，仍保留500毫秒最终回读。同步输入被网站拒绝时停止后续填写，回读重新核对字段名与经历位置，避免“值还在但位置变了”仍报成功。

本地工作台及自动日志增加扫描、匹配、执行的分阶段耗时与白名单计数，无新增权限或网络上传。四种虚构表单各6对的本机对照48次均独立核对通过，400字段同一区块的中位总耗时减少23.6%；其他场景幅度不同，不是所有网站的速度保证。方法、完整范围与复现命令见 [0.8.1 执行优化与准确性验证](docs/JEV-LOCAL-0.8.1.md)。

## 从这里开始

在 Chrome / Edge 开发者模式中加载 `extension` 文件夹，在具体申请页面点击工具栏图标。第一次选择 **MD、JSON 或 TXT** 文件，检查识别出来的字段和经历，点击“已核对，保存到本地并扫描”。之后再从申请页打开插件，会读取已经保存的资料并自动扫描，无需重新导入或输入口令。最后核对映射，点击“已核对，填写所选项”。不自动提交。

**免口令资料是在这台浏览器中未加密保存，不是“自动加密且自动解锁”。** 首次保存前显示说明并要求用户主动确认。原加密库不会自动被转换、覆盖或删除，共用电脑建议使用右上角“加密库 / MCP 高级模式”。

## MD 还是 JSON？

两者均可。多段教育、工作、项目经历推荐 JSON，字段和经历关系更明确；习惯写文字可以用模板 MD。模板里只有虚构资料：

- [JSON 模板](extension/examples/local-profile.json)：`facts` 数组，条目包含 `label`、`value`、`section`、`entity`（分区和经历标识）。ID、来源可以省略，导入时会生成。
- [MD 模板](extension/examples/local-profile.md)：`## 教育经历` + `### 本科经历` + `学校：…`，也支持“字段 / 内容”两列表格。

识别依靠明确字段，不使用模型猜测。没有字段的说明段落、代码块、不支持的表格会列为未归类，不能冒充全部已读。重复条目跳过，变化默认不选，同一文件中的冲突不会写入；保存所选项时同时确认真实性。JSON Resume 原有导入仍可用。

## 已有加密资料怎样不再反复输入口令

进入“导入与管理资料” → “从已有加密库导入”，输入原口令一次，检查预览后确认把所选条目复制到免口令本地存储。**原加密库字节保持不变**；新副本未加密，此后本地速填无需该口令。忘记原口令不能解密旧资料，必须重新导入源文件。要继续保持加密，就保留高级模式的锁定机制；是否使用 MCP 与是否加密是两件事。

## 自动问题日志

本地速填默认自动记录，无需每次先手动开启。记录读取/导入、扫描、映射、绑定、填写/回读和停止的固定阶段、耗时、计数、匿名字段序号及状态。不包含姓名等资料值、字段标签、URL、文件名、Cookie、口令、配对码、HTML、截图、原始错误或调用栈。

最多保留80次操作，每次300条字段结果，优先记录非成功状态；超过24小时的记录在下次读取或写入时淘汰。可随时关闭或清空。“自动问题日志 → 预览并导出”生成相对时间的 JSON，**不会自动上传 GitHub 或其他服务器**。操作序列和数量仍属于活动信息，分享前请检查。日志是尽力记录，后台被结束或存储故障时可能漏记，不因日志失败重复填写。

编号对应当次扫描，不是跨网站的定位器；日志用于区分匹配、权限、目标变化和校验问题，未知组件仍可能需要虚构最小页面才能重现。此日志覆盖新的本地速填入口，不宣称为旧高级 MCP 面板的全链路日志。

## 本次保留与限制

保留已有字段匹配、整段经历绑定、真实节点高亮、长表单分页、现有内容保护、日期精度限制、原生格式校验及500毫秒最终回读。明确确认后只填写选中项，敏感字段默认不选。新的资料修改、页面导航、后台重启或计划过期会使旧计划失效，需重新扫描。

本地默认路径没有模型请求或桥接等待，未为提速删除回读。仅有上文虚构表单对照，不是招聘官网或“所有网站都支持”的结论。主文档常见控件可用；同源 iframe 在高级模式仍为只读扫描，跨域框架、闭合 Shadow DOM、复杂级联、虚拟列表、附件服务器回执仍需专门验证。

本次延续0.8.0已同步的本地优先路径，没有重传此前未同步的0.7.x候选模块。**本包不包含那些候选中的 DOCX 提取、命名方案和剪贴板功能。** 本轮明确支持的是 MD/JSON/TXT、免口令持久化、一次核实后的直接扫描及自动脱敏日志。

## 高级模式与安全

右上角打开原加密库/MCP工作台，不会自动把免口令资料共享给模型。MCP原流程仍保留。曾经开启MCP时，先主动“停止共享并切回本地”；有效临时授权撤销需要桥接确认，已过期授权不应要求离线桥接再次确认。

本地 `chrome.storage.local` 仅向可信扩展上下文开放，不使用 `sync`。新本地页面的 CSP 禁止 `connect-src`；后台本地控制器不调用网络。加密模块、旧主档和可选本机桥接仍保留。静态加密或免口令模式均不能防止已攻陷的浏览器/操作系统；本机 MCP 是配对码保护的 loopback HTTP，不是TLS。详情见[本地操作说明](docs/LOCAL-FIRST-0.8.0.md)。

## 开发验证

```bash
npm test
npm run check
python -m pip install -r requirements-test.txt
python -m playwright install chromium
npm run test:local
npm run test:local-mv3
npm run test:jev
```

原有DOM/UI、MCP和安装测试继续运行。`test:local`是实际界面和Node控制器，但查询参数、Chrome存储及网页执行器为模拟；`test:local-mv3`在允许扩展加载的完整Chromium中安装临时副本，真实验证浏览器存储、自动扫描、DOM结果、重启恢复和无观察到的外部/MCP请求。它只预授权虚构localhost来源并模拟工具栏来源授权，不覆盖权限提示、实际工具栏点击或招聘官网。不得把不可用或跳过的测试记为通过。

升级先备份，在原安装路径更新并重新加载；不要先卸载或清空存储。MCP用户同时更新 `bridge` 和 `extension`，仅重启对应 `resume_fill` 进程。不要把真实资料、配对码或口令提交到公开仓库。
