# 简历填写助手 0.4.3 · 私有资料工作台

**在插件里保存、选择和核实资料，本地扫描与填写；需要时再把所选资料临时授权给 MCP / Codex。** Chrome / Edge Manifest V3 扩展；本地模式无模型调用、无填表云、无遥测。不是所有招聘网站均已验收的商店正式版。

## 这次真正接上的功能

工具栏打开新的独立工作台，分为填写、资料、安全三个页面。支持手动编辑、TXT / facts JSON / “字段：内容”粘贴导入、逐项确认、加密备份和恢复、主动锁定及口令更换。导入不会自动确认真实性。PDF / DOCX 自动解析和命名多简历版本不在本版本。

扫描只使用本次勾选的已核实资料。预览默认隐藏值，敏感项目默认不勾选。姓名、联系方式和多段经历用分区、标签与明确映射区分；位置不确定时留给用户处理，不按数组顺序猜测。本地填写只把选中字段发送给目标 Chrome 文档，核对计划、资料修订号、文档标识、现有值后执行，不自动提交。

同源 iframe 可以在单独授权后枚举和扫描，**嵌入文档目前只读**；自动填写前需单独打开成主页面重新授权。跨域、特殊文档、折叠/隐藏控件及复杂控件不能算作已经覆盖。当前保留原 0.4.1 执行器，不展示尚未实现的精确高亮按钮。扫描数量不是整站完整率。

## 三种明确分开的数据路径

| 路径 | 数据来源 | 网络与持久化边界 |
| --- | --- | --- |
| 本地填写（默认） | 插件加密资料库中本次选择的事实 | 不调用桥接或模型；执行时把所选值交给当前招聘网页 |
| 临时 MCP 协作 | 工作台扫描后明确授权的事实与主页面字段结构 | 本机桥接内存中最多5分钟；不写入旧主档、证据、历史映射或审计；授权资料会进入 Codex 上下文 |
| 原 MCP 主档 | 用户主动切换后的旧 profile.json / evidence.json | 仍为本机明文；保留原维护主档、材料检索及填表流程 |

本地模式无需 Node，也无需配对。临时协作可在“安全中心”直接验证本机配对码，不必先切换到旧明文主档。验证只访问固定的 `127.0.0.1:19327/status`，拒绝重定向与不兼容桥接，失败不覆盖旧配对码。

临时授权撤销或到期后拒绝后续读取，并清除桥接中的资料与计划值；正在执行的任务保留锁，等待实际执行器回报。网页写入属于外部副作用，已进入网站或模型上下文的值不能靠撤销收回；浏览器崩溃或挂起时也不能保证即时停止。

## 开始使用

加载 `extension` 文件夹，不是仓库根目录。首次使用在具体申请页点工具栏图标，创建独立长口令，导入并核实资料。勾选本次资料 → 扫描 → 查看待填项/保留项/缺项 → 核对映射 → 勾选授权 → 填写 → 检查回读。详情见 [安装与操作](docs/INSTALL-0.4.3.md)。

旧用户先备份，不要卸载扩展或清空浏览器存储。继续使用 MCP 时，**同时更新 bridge 和 extension**；保留仓库外的私有数据目录，只重启对应的 resume_fill 桥接。

原来的 MCP 配置入口保持为 `node bridge/server.mjs`，需要 Node.js 22 或以上。配对码、口令、真实简历和主档不要发到 GitHub。没有从公开源码自动恢复私有资料的功能。

## 速度与正确性

保留已合并的扫描缓存、单计划语义索引、事件等待、通知唤醒及500毫秒最终延迟回读。这一轮不通过删除回读或放宽定位校验提速。独立工作台在本地路径中没有 MCP 通知往返或模型请求；这不等于所有控件立即完成。

历史对照：[DOM 性能](docs/PERFORMANCE.md)、[通知与资料准备](docs/RESPONSIVE-FILL-0.3.2.md)。它们描述对应旧提交的测试，不是本版本对真实招聘网站的新速度承诺。不得把命令通知的毫秒数宣传为整表完成时间。

GitHub Actions 对提交执行检查并生成源码/扩展产物，CI 不读取真实用户资料、不部署、不自动合并。所有示例与截图只用虚构数据。

## 安全与产品参照

[安全模型](docs/PRIVACY-0.4.3.md)解释浏览器隔离、密文存储、MCP 传输和残余风险。认证加密不能抵御已攻陷的操作系统/浏览器，也不能阻止招聘网站收集已经填写的值。loopback HTTP 加配对码不等于加密传输或抵御本机高权限窃听。

用户指定的[塔塔网申](https://tatawangshen.com/)作为产品目标，官方页面宣传一键填写与多份简历等能力；本项目没有与之完成相同条件的真实站点对照，不宣称已经超越。其帮助页本次文本抓取无正文，未据此编造兼容平台清单。产品目标转化为：可查数据范围、可确认映射、可撤销后续授权、可复现失败与独立结果检查，而不是无法验证的“全站零误填”。
